---
title: AI
description: Product descriptions and search listings written by AI, from Shopnex itself or from apps.
---

Shopnex shows a ✨ **Generate** button next to a product's description and its search engine listing whenever an AI
**capability** is available. Results are suggestions: **Use this** puts the text into the form, and nothing is saved
until staff press Save.

Shopnex owns the commerce side: who may ask, which product data is used, and what gets saved. Every run is kept as a
generation with its usage and whether staff used the suggestion.

## Built-in AI

Owners and admins turn it on under **Settings → AI**: pick **Claude** (Anthropic) or **OpenAI**, paste the shop's own
API key, and optionally a model and a brand voice applied to everything written for the shop. Saving checks the key
with the provider first. The key is stored encrypted, like email passwords, and generations are billed to the
shop's account with the provider. Turning AI off deletes the key.

It runs inside Shopnex: no extra service, domain or environment variable. The provider SDKs are loaded the first
time a shop uses them.

```text
Admin ✨ Generate → POST /admin/ai/run → Shopnex loads the product → Claude / OpenAI (the shop's key)
```

## Capabilities

| Capability            | Input                               | Output                   |
| --------------------- | ----------------------------------- | ------------------------ |
| `product.description` | `tone?`, `length?`, `instructions?` | `{ descriptionHtml }`    |
| `product.seo`         | `instructions?`                     | `{ title, description }` |

Schemas live in `@shopnex/marketplace-sdk/ai` (`aiCapabilities`). Capabilities only change additively; a
breaking change gets a new name.

## Provide a capability from an app

Built-in AI answers first when it's on. Apps can provide capabilities too, for example a translation service or
another model provider, and staff can pick them in the Generate dialog.

Register the app with the `write_ai_capabilities` scope. Once the merchant has entered a provider key, tell
Shopnex what you provide:

```ts
await shop.ai.configure({
  'product.description': `${APP_URL}/ai/run`,
  'product.seo': `${APP_URL}/ai/run`,
})
```

URLs must be on the app's own origin. Each call replaces the previous set; `{}` provides nothing.

Shopnex then POSTs a signed `AiRunRequest` containing the capability, the staff's input and a snapshot of the
product (title, description as text, options, variants with prices, tags, images, collections). The app never
needs `read_products`. Answer within 60 seconds:

```ts
app.post('/ai/run', async (c) => {
  const { request, shop } = await shopnex.verifyAiRequest(c)
  const apiKey = await shop.data.getSecret('provider_key')
  switch (request.capability) {
    case 'product.description': {
      const html = await writeDescription(apiKey, request.subject.product, request.input)
      return c.json({ output: { descriptionHtml: html }, usage: { model: 'my-model' } })
    }
    case 'product.seo': {
      const seo = await writeSeo(apiKey, request.subject.product, request.input)
      return c.json({ output: seo })
    }
  }
})
```

Shopnex checks the answer against the capability's output schema (a mismatch is a 502 for staff) and sanitizes
HTML, the same as for built-in AI.

## Admin API

- `GET /admin/ai/capabilities`: available capabilities and who provides them (`builtin` first, then apps).
- `POST /admin/ai/run` `{ capability, productId, input?, providerId? }`: needs `read_products`. `providerId` is
  `builtin` or an app's id; the default is the first provider. Returns `{ id, provider, output, usage }` without
  saving anything.
- `POST /admin/ai/generations/{id}/feedback` `{ feedback: 'accepted' | 'rejected' }`.
- `GET`, `PUT`, `DELETE /admin/ai/settings`: built-in AI (owners and admins). `PUT` takes
  `{ provider, apiKey?, model?, brandVoice? }`; the key is never returned.
- `POST /admin/ai-app/configure` `{ capabilities }`: AI app tokens only.
