ShopNex ships as one image containing the admin, API, hosted checkout and the default storefront, fronted by Caddy on a single port. Two ways are fully supported: one-click deploys on Render and DigitalOcean, and the install script on your own server.

## One-click deploy

No server to manage. Each of these creates the app and a Postgres database for you.

## Your own server

The cheapest way to run ShopNex long term, if you are comfortable with a terminal. You need a fresh Linux server with at least 2 GB of memory and a domain. Point two DNS records at the server first: `shop.example.com` for the shop and `stripe.shop.example.com` for the Stripe app. The installer sets up Docker, Postgres and ShopNex, and gets HTTPS certificates automatically.

<CodeBlock title="Terminal">
  <Pre className="px-4">
    <code>{`curl -fsSL ${SITE_URL}/install.sh | sudo SHOPNEX_DOMAIN=shop.example.com sh`}</code>
  </Pre>
</CodeBlock>

Then open your domain and finish the setup wizard.

<Callout type="warn" icon={<ShieldAlert />}>
  Without `SHOPNEX_DOMAIN` the shop runs over plain HTTP on the server's IP address. That is fine for a quick test, but
  do not create your admin account or take orders that way.
</Callout>

## How the image is wired

- **Admin, API and checkout** (`/admin`, `/api/*`, `/checkout/*`, plus admin assets) go to the admin app.
- **Everything else** (`/`, `/products`, `/collections`, `/pages`, theme assets) goes to the storefront.

Every option above runs this same image, so a platform only needs to forward one port and give the app a Postgres `DATABASE_URL`.
