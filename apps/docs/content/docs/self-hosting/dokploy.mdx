Platforms that run Docker Compose on your own server can deploy Shopnex and its Stripe app from versioned prebuilt images plus a Postgres database. Nothing is built on the server. The production Compose file is [`deploy/docker-compose.yml`](https://github.com/shopnex-ai/shopnex/blob/main/deploy/docker-compose.yml); pin `SHOPNEX_VERSION` to a release tag for production.

## The compose file

Use [`deploy/docker-compose.yml`](https://github.com/shopnex-ai/shopnex/blob/main/deploy/docker-compose.yml) as is. It is the same file the installer and the in-app updater use. Download it with:

```sh
curl -fsSLO https://raw.githubusercontent.com/shopnex-ai/shopnex/main/deploy/docker-compose.yml
```

Every variable has a local default, so `docker compose up` works without any setup (add `-d` to run it in the background). For a public deployment set these on the platform:

| Variable            | Description                                                                                           |
| ------------------- | ----------------------------------------------------------------------------------------------------- |
| `APP_URL`           | Public origin, e.g. `https://shop.example.com`. Default `http://localhost:3000`.                      |
| `STRIPE_APP_URL`    | Public origin for the Stripe app, e.g. `https://stripe.example.com`. Default `http://localhost:4600`. |
| `POSTGRES_PASSWORD` | Password for the bundled database. Change it from the default.                                        |
| `SHOPNEX_VERSION`   | Release tag for both images, e.g. `v1.2.3`. Default `latest`; pin a tag in production.                |

**Optional apps.** The CJ Dropshipping app is off by default. Enable it with `COMPOSE_PROFILES=cj` (or `docker compose --profile cj up`); Shopnex finds it on the Compose network. For a public domain set `CJ_DROPSHIPPING_APP_URL` (e.g. `https://cj.example.com`) and route that domain to port `4700` of the `cj-dropshipping` service. The same applies to `STRIPE_APP_URL` and the `stripe` service.

`BETTER_AUTH_SECRET` is optional: when empty, the image generates one into the `shopnex_data` volume, so keep that volume. See [Configuration](/docs/self-hosting/configuration) for the other variables.

## Dokploy

Use [`deploy/docker-compose.dokploy.yml`](https://github.com/shopnex-ai/shopnex/blob/main/deploy/docker-compose.dokploy.yml), the same stack without published host `ports:`. Dokploy's proxy reaches the containers over the Docker network, and a published port such as `3000` can collide with it or with another app and fail the first deploy.

1. Create a **Compose** service in a project and choose the **Raw** provider.
2. Paste the Dokploy compose file and set `APP_URL`, `STRIPE_APP_URL`, `POSTGRES_PASSWORD`, and `SHOPNEX_VERSION` under **Environment**.
3. Under **Domains**, add the Shopnex host with service `shopnex` and port `3000`, plus the Stripe host with service `stripe` and port `4600`. Enable HTTPS and point both DNS records at the server.
4. Click **Deploy**.

To update, change `SHOPNEX_VERSION` to the desired release tag and deploy again. `pull_policy: always` fetches that tagged image. Shopnex and Stripe use the same release tag.

## Coolify, Portainer and others

Any platform that accepts a compose file works the same way: Coolify (a Docker Compose resource), Portainer (a stack from the web editor), or plain `docker compose up -d`. Route the Shopnex domain to port `3000` and the Stripe domain to port `4600`; let the platform's proxy handle HTTPS. For plain Docker Compose without a proxy, publish both ports on the host.

The container already includes Caddy, which routes the admin and API to the admin app and everything else to the storefront, so the platform only needs to forward one port.

<Callout type="warn">
  Open the deployed URL and complete `/admin/setup` immediately: a fresh install can be claimed by whoever gets there
  first.
</Callout>

## Servers with little memory

Use the prebuilt image rather than building on the server. The build needs far more memory than running the shop does, and can fail on a 2 GB machine.
