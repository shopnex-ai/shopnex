import { SITE_URL } from '@/lib/site'

The installer sets up Docker if needed, then runs the released Shopnex images and a Postgres database with Docker Compose in `/opt/shopnex`. Nothing is built on your server. You need a fresh Ubuntu or Debian server with at least 2 GB of memory.

<code>{`curl -fsSL ${SITE_URL}/install.sh | sh`}</code>

When it finishes, open the address it prints and complete the setup wizard at `/admin/setup`.

<Callout type="warn">
  Complete the setup wizard right after installing. Until you do, anyone who finds the address could claim your shop.
</Callout>

## Use your own domain

Point three DNS records at the server: `shop.example.com` for the shop, `stripe.shop.example.com` for the Stripe app and `ai.shop.example.com` for the AI app. Then run the installer with the domain. HTTPS is set up automatically.

<code>{`curl -fsSL ${SITE_URL}/install.sh | SHOPNEX_DOMAIN=shop.example.com sh`}</code>

To use different names for the apps, also set `SHOPNEX_STRIPE_DOMAIN` or `SHOPNEX_AI_DOMAIN`.

Installed before the AI app existed? Updates keep working without it. Add the `ai.` DNS record and run the install command again to turn it on.

## Options

| Variable                | Default                   | What it does                                  |
| ----------------------- | ------------------------- | --------------------------------------------- |
| `SHOPNEX_DOMAIN`        | the server's IP address   | Public domain. Turns on HTTPS.                |
| `SHOPNEX_STRIPE_DOMAIN` | `stripe.<SHOPNEX_DOMAIN>` | Domain for the Stripe app.                    |
| `SHOPNEX_AI_DOMAIN`     | `ai.<SHOPNEX_DOMAIN>`     | Domain for the AI app.                        |
| `SHOPNEX_VERSION`       | the latest release        | Release tag to install, for example `v1.2.3`. |
| `SHOPNEX_DIR`           | `/opt/shopnex`            | Where the Compose file and `.env` are kept.   |

## Update

When a new release is out, the admin shows **Update available** at the bottom of the sidebar (super admins only). Click it, then **Update**. Shopnex takes a database backup, switches to the new version, and rolls back to the old one if the new one does not start. Expect a minute or two of downtime.

You can also run the install command again, or set `SHOPNEX_VERSION` to a release tag. Nothing is ever updated without a click.

Backups are written to `/opt/shopnex/backups` before every update, and the five newest are kept. A rollback restores the old version of Shopnex but cannot undo database changes the new version already made, so restore from the backup if you need to go back further.

### How the update button stays safe

The Shopnex container has no access to Docker. A small script owned by root runs on the server (`/usr/local/sbin/shopnex-update`, started by a systemd path unit) and does the update. The app can only write a version number into one folder, and the script refuses anything that is not a published, newer release. The app can read the progress the script reports but cannot change it.

To turn the button off, remove the script and the watcher:

```sh
sudo systemctl disable --now shopnex-update.path
sudo rm /usr/local/sbin/shopnex-update
```

## Moving from the older installer

Earlier versions of the installer ran Shopnex directly on the server, with Node and Postgres installed on the host and no Docker. The new installer refuses to run on such a server, because it would start a new, empty shop next to your real one.

There is no automatic migration yet. Until there is, your existing shop keeps running as it is. If you want to move it to Docker, first save two things from the old server:

- a database dump: `sudo -u postgres pg_dump shopnex > shopnex.sql`
- the `BETTER_AUTH_SECRET` line from `/opt/shopnex/.env`. Saved provider keys are encrypted with it and cannot be read without it.

Then [open an issue](https://github.com/shopnex-ai/shopnex/issues) and we will help you move it.

## Manage it

Everything lives in `/opt/shopnex`. Your settings are in `.env`.

```sh
cd /opt/shopnex
docker compose logs -f shopnex   # logs
docker compose ps                # what is running
docker compose restart shopnex   # restart
```
